# Wikinote 产品、代码与视觉审计

日期：2026-09-05。基线：`main` / `b84d774`（2.1.0）。本轮修改未提交、未发布。

后续更新：用户确认保留动态体验后，完成了重点背景的[专项打磨](theme-polish-2026-09-05.md)。下文保留首轮审计记录；背景卸载、星空元数据对比度等问题以该后续记录为准。Solar 的夜间配色实际上仍偏浅，未确认夜间文字不可读问题，不应仅凭相位名称推断。

## 结论

这个产品的核心不是「聚合信息面板」，而是「在打开标签页的间隙，重新遇见一段值得读的内容」。Chrome 插件是主场景；网页版复用同一套阅读体验。微信读书适合作为私人阅读记忆源，不适合在首页堆砌书架、统计和热门榜单。

当前代码并非没有架构：`SourceAdapter`、统一的 `DiscoveryItem`、数据源注册表、查询缓存和收藏上下文提供了合理边界。无需更换框架、增加后端或搭建通用插件运行时。真正的短板是跨标签页状态一致性、缓存及身份边界、失败状态和行为测试，而不是文件夹不够多。

本轮完成了微信读书的代码接入和一组明确的质量修复，并统一了默认阅读体验的调性。它仍是待真实账号验收的候选版本，不能把模拟接口测试或构建成功等同于真实服务已联调成功。

## 审计范围与方法

检查了入口和构建配置、五种内容源、查询/增量加载、缓存、权限和凭证存储、收藏/最近阅读/同步、翻译、主题与动画、弹窗/键盘交互、打包脚本、CI、依赖及隐私说明。采用代码审阅、模拟接口行为测试、生产构建和浏览器实际页面检查。

这不是安全渗透测试，也不是所有浏览器、11 个主题、全部语言和辅助技术的认证。没有用户真实 WeRead Key、Memos/Hypothesis 私人测试账号，未执行商店发布。没有采集首屏耗时、帧率或电量的基线，因而不宣称具体百分比的性能提升。

## 微信读书：已实现的范围

依据腾讯[官方 WeChatReading 仓库](https://github.com/Tencent/WeChatReading)、[Skill 入口](https://github.com/Tencent/WeChatReading/blob/main/skills/SKILL.md)及[笔记接口说明](https://github.com/Tencent/WeChatReading/blob/main/skills/notes.md)实现，而非使用 Cookie 抓取或非官方代理。

- 配置入口：Sources → 微信读书 → 官方 Key 获取入口 → Save & connect。
- 仅在用户设置/启用时申请 `https://i.weread.qq.com/*` 权限；没有新增安装时的必需主机权限。
- POST Agent Gateway，Bearer API Key，扁平参数和 `skill_version: 1.0.4`。
- 使用 `/user/notebooks`、`/book/bookmarklist`、`/review/list/mine`。保留接口大小写差异：`bookId` 与 `bookid`。
- 逐页遍历笔记书目，随机化书目顺序；单批最多返回 30 条，保留剩余内容和翻页游标。单次最多探查三个空书目/页面，避免每个新标签页下载整个书库。
- 匹配同章、同范围的划线和想法；保留引用与用户想法的语义区别。纯书签、空文字不进入阅读流。
- 展示书名、作者、章节；支持收藏、检索、导出。没有 API 返回的可靠链接时不构造阅读地址。
- 身份摘要隔离游标和条目，支持取消、请求超时和明确的授权/限流/升级错误；失败不提交翻页进度。支持 Web Locks 的环境按账号串行更新游标。
- Key、内容缓存和微信读书收藏保留本地；微信读书收藏及其删除记录不进入 Chrome Sync。
- 断开连接删除配置和抓取缓存，保留用户已收藏内容与最近阅读记录；清理二者需要单独操作。

限制：Key 的 SHA-256 摘要是本地隔离标识，不是服务端账号 ID，也不是对存储内容加密；更换同一账号的 Key 会形成新条目身份。网页登录受官方 CORS 行为影响，本次网络预检未能确认其支持情况；产品不增加后端代理来绕过。发布前必须在 Chrome 插件内用真实 Key 验收。

## 本轮已经修复或改善

| 领域 | 原问题与影响 | 本轮处理 |
| --- | --- | --- |
| 缓存身份 | 指纹截断至 40 字符，相同长 URL 前缀下可能混淆不同配置 | 保留完整非秘密配置身份；使用配置修订 ID，不在查询/存储键中拼接凭证；缓存版本升级 |
| 请求生命周期 | 配置切换后旧的增量请求可能把旧源内容合入当前阅读流 | 增加请求取消、源身份检查、增量结果隔离及阅读锚点隔离 |
| 权限 | 配置保存/启用与主机授权之间存在时序问题 | 从 Save/启用手势等待权限结果，拒绝授权不保存新配置 |
| 失败状态 | 部分源失败或空数据缺少可见解释 | 设置页源状态、阅读页提示、空内容重试入口；避免配置型源无意义重复重试 |
| 本地删除 | Chrome 本地存储删除后仍可能从 localStorage 镜像恢复 | 同时删除镜像，加入回归测试 |
| 内容质量 | Wikipedia 消歧义页、空或极短摘要进入阅读流 | 请求消歧义标记并过滤无效摘要，加入行为测试 |
| 最近阅读 | 首次内容可能在收藏状态尚未初始化时被跳过 | 初始化完成后重新执行最近阅读记录 |
| 无障碍 | 阅读首页被当作模态弹窗、空状态入口不完整、工具栏只考虑鼠标 | 去掉首页焦点陷阱；弹窗保持局部焦点管理；补空状态弹窗和键盘/触摸唤醒 |
| 视觉与动画 | 正文、设置、收藏之间调性不一致，背景对正文有干扰 | 统一阅读配色与衬线字；压低波浪；隐藏页面暂停背景；尊重系统减少动画设置 |
| 依赖与交付 | 构建链存在已知漏洞，缺少独立行为测试，打包依赖未转义 shell 字符串 | 更新依赖；sharp 移入开发依赖并升级；新增 Vitest；CI 增加测试及网页版构建；打包参数化执行并校验入口/图标 |
| 隐私说明 | 关闭同步被误解为云端删除，Hypothesis 查询范围说明不准确 | 明确关闭同步只停止本机同步；纠正私人源的真实存储/请求范围及断开语义 |

## 尚未解决的发现与优先级

以下主要为静态代码路径确认的风险；没有把未经执行的多设备场景写成已经复现。P1 建议优先处理，P2 为常规可靠性改进，P3 为整理项。

### P1：多标签页收藏可能互相覆盖

位置：`frontend/src/contexts/LikedArticlesContext.tsx` 的 `recordsRef`、`persistLocal`、`toggleLike`。

每个标签页独立初始化整份收藏，再按整份快照写回；关闭云同步时没有监听其他标签页的本地收藏变化。若 A/B 同时打开，A 收藏一条后 B 用旧快照收藏另一条，B 的保存可能覆盖 A 的内容。最近阅读也采用整份写回。微信读书收藏是本地内容，因此同样受这一旧问题影响。

建议先补双标签页交错读写测试，再做每次写入前读取合并、同源锁和变更广播；没有必要为此引入后端。

### P1：断开私人源不是跨标签页即时撤销

位置：`frontend/src/contexts/SourcesContext.tsx`、`frontend/src/utils/feedCache.ts`。

当前标签页可以删除配置与缓存并取消本页请求；其他已打开页面不监听配置变化，仍可能持有旧 Key 和在途请求，随后重新写入内容缓存。界面“断开”也不等于向服务端吊销 Key。

建议统一源配置变更事件、跨页取消/撤销代次，并在写缓存时再核验代次。现阶段断开前关闭其他 Wikinote 标签页；如需真正撤销访问，到官方服务吊销 Key。不能对跨页即时清除作保证。

### P1：Hypothesis 的“我的内容”边界不完整

位置：`frontend/src/sources/hypothesis.tsx` 的 `fetchAnnotations` 和 `configSchema`。

`username` 可选，只有填写时才附加 `user=acct:…@hypothes.is`。Token 负责认证，但不等于搜索过滤器；未填写时可能读到其他用户的公开标注。隐私说明和 README 已纠正，功能行为尚未改变。

若产品决定它始终只展示“我的内容”，应通过官方账户资料解析用户身份，或把 username 设为必填并提示旧配置补全，而不是仅调整文案掩盖问题。

### P2：旧内容源条目 ID 缺少命名空间

位置：`frontend/src/sources/wikipedia.tsx` 的 `wiki-${pageid}`，`frontend/src/sources/memos.tsx` 的 `memo-${uid}`。

Wikipedia 不同语言站点的 pageid 可能相同；Memos 不同实例的 uid 也没有在模型层保证全局唯一。切换语言或实例后收藏可能被当成同一项。需要把站点/实例纳入 ID，并迁移旧收藏，不能只改 ID 字符串而丢失收藏关联。本轮 WeRead 新条目已独立隔离，但没有迁移旧源。

### P2：同步协议存在跨设备写入竞争

位置：`frontend/src/utils/favoriteSync.ts` 的 `writeFavoriteSyncRecords`。

同步块用固定索引键，多个设备可并发覆盖相同块；写入后清理旧块也没有跨设备原子事务。当前“先读合并再写”只减少冲突，不能消除。建议测试双设备交错写入/删除/配额耗尽，评估带代次的不可变块与可恢复清理；此类协议变更应单独交付并验证迁移。

### P2：存储与旧数据校验仍不统一

位置：`frontend/src/utils/environment.ts`、`SourcesContext.tsx`、`LikedArticlesContext.tsx`。

Chrome local 的 get/set/remove 对 `runtime.lastError` 处理不如 sync 完整；部分 localStorage 读写没有异常保护；旧收藏校验不足以保证 `source` 属于注册表和 `raw` 满足各来源结构。配额、禁用存储或损坏数据可能导致未处理异常或错误的“已保存”状态。建议收敛到小型存储边界与来源校验函数，不必引入完整数据框架。

### P2：翻译等待没有绝对截止时间

位置：`frontend/src/utils/translation.ts` 的 `useAutoTranslatedText`、`translateTitle`。

当前有激活重试和 fallback，但 `create/prompt/translate` 若一直不 resolve，`inFlight` 仍为真，原文又在 pending 时隐藏，标题可能长期空白。应给显示层增加硬截止时间和原文兜底，并测试永不完成的模型调用。未在真实 Chrome 本地模型环境复现。

### P2：主题对比度与环境支持还需专项验收

位置：`frontend/src/components/ZenMode.tsx`、`components/zen/SolarTheme.tsx`、扩展 manifest。

Solar 昼夜变化在背景内部，正文前景仅依据静态 `theme.dark`；需要把时间相位传给统一色板，并逐主题检查对比度。当前 manifest 的 connect-src 只允许 HTTPS，但可选主机权限仍包含 HTTP；自托管 Memos 的 HTTP 地址会被 CSP 阻止。文档已明确要求 HTTPS，后续可在输入处提前校验。

### P3：组件与工程债务

- `ZenMode.tsx` 同时承担布局、主题、阅读导航、分享、工具栏、弹窗与阅读恢复，建议按 `ReadingContent` / `ReaderControls` / `ThemePicker` 拆分，不要切成大量无意义的小文件。
- `App.tsx` 的查询编排可提为 `useDiscoveryFeed`，但应先有配置切换/并发加载行为测试。
- 当前首页固定使用阅读模式，旧卡片渲染契约仍会引入组件；确认不再使用网格模式后再删除，避免盲目清理预留能力。
- `useLocalization` 多实例各自初始化和写存储，可逐步由一个 Provider 维护；不需要再加一套全局状态库。
- 部分打包辅助步骤捕获错误后继续；本轮增加最终入口/图标检查，后续可进一步统一失败退出与产物校验。
- 原有 `verify-regressions.mjs` 多为源码文本断言，重构会误报；保留作过渡，逐步由行为和产物测试替代。

## 视觉方向与已落地内容

我的建议是做“有编辑感的私人阅读空间”：识别度来自比例、文字和安静的色彩，而不是叠加更多特效。

- 配色：纸白 `#faf8f3`、墨色 `#29332e`、灰绿 `#69766d`、强调绿 `#526e5e`；设置和收藏复用同一套面板语言。
- 字体：本地优先的中文宋体/衬线字组合；正文与标题按内容类型区分，而不是所有内容统一放大。移除 Google Fonts 外部导入，降低首屏外部依赖。
- 排版：引用用细边线，想法单独分区；书名/作者/章节退到出处层级。较长内容可滚动，避免与底部操作争夺空间。
- 动效：阅读切换缩短为轻位移/淡入；背景波浪压低、减淡并限制渲染像素比；页面隐藏或用户要求减少动画时停止背景。
- 交互：工具栏仍低干扰，但键盘和触摸也可唤醒；焦点可见，不让首页像模态框一样锁住用户。

暂未重画所有主题，也没有引入图片素材或外部设计系统。下一轮最有价值的是收敛 2–3 个主推主题的完整色板和内容模板，而不是继续增加主题数量。

## 验证结果

本轮本地完成：

- `npm test`：3 个测试文件、30 项通过。涵盖 WeRead 请求协议、错误、取消、个人内容归一化、账号隔离、分页/队列、失败游标不提交；缓存隔离、镜像删除、微信读书同步排除；Wikipedia 消歧义及摘要过滤。
- `npm run lint`：通过。
- `npm run build:web`、`npm run build:extension`：通过，均包含 TypeScript 检查。
- `npm run pack:extension`、`npm run verify:regressions`：通过；32/48/128 图标由升级后的 sharp 成功生成。
- 依赖更新后 npm 检查：0 项已知漏洞。这只代表检查时的依赖公告结果，不等于应用不存在安全问题。
- 浏览器检查了实际阅读组件、设置面板和微信读书示例排版；开发示例明确标注为原创演示内容，不冒充真实书籍或用户笔记。窄屏语言行作了布局调整；完整移动端和辅助技术矩阵仍待验证。

生产扩展当前约 290.12 kB 主 JS + 139.87 kB vendor + 0.82 kB runtime + 68.15 kB CSS（未压缩）。没有同环境性能基线，不据此声称变快。

## 发布前验收清单

1. 加载 `frontend/dist/extension/`，以真实 Key 测试首次授权、拒绝授权、重新授权、401/403 和重连。
2. 用有划线/想法、没有笔记、超过一页书目和超过一页想法的账号数据验证，不发送真实 Key 到日志或聊天。
3. 测试切换 Key、断开、关闭重开、多标签页同时打开及收藏保留；优先处理上面两项跨标签页 P1。
4. 检查无官方 deepLink 时不存在坏链接，收藏/搜索/导出正常，开启 Chrome Sync 后没有微信读书正文和 Key。
5. 在目标 Chrome 版本、所有主推主题、中文长文、200% 缩放、纯键盘和减少动画设置下验收。
6. 另行决定版本号和发布安排。本轮未创建 commit、PR、tag 或商店发布。
